# OmniSign Web

OmniSign Web is the OmniSign desktop application running in a browser — the same interface, with
nothing to install. Open a PDF, read its signatures, sign it, or extend an existing signature. The
cryptography is carried out by the [OmniSign Server](/server/) your organization runs, which the
browser talks to over HTTP.

:::info[The one thing to understand before you start]
A browser cannot reach a smart card and never sees a private key. **Documents are signed by the
server, using the server's own signing certificate** — not a certificate of yours. In the browser you
choose *which* of the server's certificates to use and *how* to sign; the signature itself is produced
server-side. See [Signing a document](guides/signing.mdx).
:::

## Quick start

1. **Open the address** your administrator gave you. There is no installer. If the server requires it,
   you will sign in first with your organization's account.
2. **Open a PDF** — click the folder icon <AppIcon name="folder" color="folder" label="Open file" />
   at the left of the toolbar and pick a file. The document is read inside the browser; nothing is
   sent anywhere yet.
3. **Read its signatures** — open the **Signature** panel <AppIcon name="signature" label="Signature panel" />
   on the left edge and press refresh. See [Validating signatures](guides/validation.mdx).
4. **Sign** <AppIcon name="sign" label="Sign" /> or **extend** <AppIcon name="stamp" label="Timestamp" />
   the document from the middle of the toolbar. See [Signing](guides/signing.mdx) and
   [Timestamping](guides/timestamping.mdx).
5. **Save the result.** The signed file comes back through the browser — either a real *Save As*
   dialog or an ordinary download, depending on your browser.

## What runs where

Opening and reading a PDF are entirely local. Every other operation sends the document to the server.

| Step                              | Where it happens                                                    |
|-----------------------------------|---------------------------------------------------------------------|
| Opening and rendering the PDF     | In your browser (the file never leaves the tab)                     |
| Page navigation, zoom, theme      | In your browser                                                     |
| Validating signatures             | On the server — the document is uploaded and a report comes back    |
| Signing                           | On the server, with the server's key and certificate                |
| Timestamping / extending          | On the server, using the server's timestamp authority               |
| Configuration, profiles, trust    | On the server — read-only in the browser                            |

Once you sign, timestamp, or validate, the document's bytes are sent to the server so it can do the
work; the server does not keep them. The browser itself stores only your interface preferences — see
[Settings → What's stored in your browser](guides/settings.mdx#whats-stored-in-your-browser).

## What you can do

- **View** any PDF, with page navigation and zoom from 25 % to 400 %
- **Validate** signed PDFs, including eIDAS EU LOTL qualification, and read the full report
- **Export** the validation report as TXT, JSON, or one of four XML formats
- **Sign** PDFs at PAdES BASELINE B-B / B-LT / B-LTA with the server's certificate
- **Extend** existing signatures to a higher PAdES level, or renew an archival timestamp
- **Inspect** every certificate in the chain, and download any of them
- **Choose** which of the server's [signing profiles](guides/profiles.mdx) applies to your operations
- **Read** the server's configuration and trusted certificates, and export the whole configuration as a ZIP
- **Switch** the interface language, date format, and dark / light theme

Which operations you actually see depends on what the server permits — a server may expose validation
only, and hide signing and timestamping entirely. See [Features](features.mdx).

## Browser support

The frontend needs **WebAssembly** with **WebAssembly GC**:

| Browser       | Minimum version |
|---------------|-----------------|
| Chrome / Edge | 119+            |
| Firefox       | 120+            |
| Safari        | 18.2+           |

If the page stays blank, the browser is almost certainly too old — see
[Troubleshooting](troubleshooting.mdx#the-page-is-blank-or-never-finishes-loading).

## Also available

The same operations run entirely on your own machine, with your own smart card or PKCS#12 file, in
the [Desktop app](/desktop/) and the [CLI](/cli/). Administrators deploying the web bundle should read
[Deployment](deployment.mdx).

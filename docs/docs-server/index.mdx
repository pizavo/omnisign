# OmniSign Server

OmniSign Server is a **Ktor/Netty HTTP backend** that exposes the same PAdES signing, validation,
and re-timestamping capabilities as the Desktop and CLI apps over a REST API — for organization-wide
deployment behind your own authentication and policy.

It is a **provider/operator-facing** component: you deploy it, an administrator configures *how* it
signs and validates and *who* may reach it, and clients (the [web frontend](/web/), scripts, or other
services) call its [API](/server/api/omnisign-server-api).

## Architecture

| Component | Technology            | Role                                                  |
|-----------|-----------------------|-------------------------------------------------------|
| Server    | Ktor / Netty (JVM)    | REST API for signing, validation, timestamping        |
| Web       | Compose / Kotlin/Wasm | Optional browser client that calls the server API     |
| Policy    | `signing.yml`         | Provider-authored signing/validation rules + profiles |

## Two configuration files

The server is configured by **two** files, deliberately separated:

- **[`server.yml`](configuration)** — *exposure and security*: network bind, TLS, CORS, reverse
  proxy, rate limiting, authentication, and which operations are allowed.
- **[`signing.yml`](signing-policy)** — *how it signs and validates*: default algorithms, signature
  level, TSA, validation policy, trusted certificates, and named profiles. This is the server's
  equivalent of the desktop "global settings + profiles", loaded read-only.

Secrets (the JWT signing key, OIDC client secrets, TLS keystore passwords) are **never** written to
either file — they are supplied through [environment variables](configuration#secrets). Two more are
referenced in the files but resolved from the environment at load: `auth.oauthStateSecret` in
`server.yml` and the TSA password in `signing.yml`, both written as `"${VAR}"` placeholders.

## Quick start

The server needs a `server.yml`. Start from the bundled `server.example.yml` (extract it from the JAR
with `jar xf <jar> server.example.yml`, or copy it from `server/src/main/resources/`):

```bash
# that path is gitignored; :server:run picks it up automatically
cp server/src/main/resources/server.example.yml server/src/main/resources/server.yml
./gradlew :server:run                 # use .\gradlew.bat on Windows
```

`:server:run` passes `--config server/src/main/resources/server.yml` whenever that file exists. A
packaged deployment instead uses `--config`, `OMNISIGN_SERVER_CONFIG`, or a `server.yml` in the
working directory.

With the defaults it binds to **`127.0.0.1:18080`** (loopback) and allows only the **VALIDATE**
operation. See [Configuration](configuration) for the full file reference and
[Deployment](deployment) for Docker, systemd, and reverse-proxy setups.

:::warning
Run behind TLS (or a TLS-terminating reverse proxy) before exposing the server beyond `localhost`.
Binding to any host other than `127.0.0.1`, `::1`, or `localhost` without a `tls:` block or
`proxy.enabled: true` is refused at startup. See [Security](security).
:::

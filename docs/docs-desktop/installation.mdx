# Installation

## Prerequisites

OmniSign Desktop ships with its own bundled JetBrains Runtime — **end users do not need to install
Java**. Building or running from source requires **JDK 25** and specifically **JetBrains Runtime
(JBR) 25** (for the Custom Title Bar API); `composeApp` pins `JvmVendorSpec.JETBRAINS` and the build
fails with a descriptive error if JBR 25 is not found.

<OsTabs>
<TabItem value="windows" label="Windows">

JBR is bundled with the MSI installer. If you run from source, install JBR from
[JBR Releases](https://github.com/JetBrains/JetBrainsRuntime/releases) or via
IntelliJ IDEA's Gradle JDK settings.

</TabItem>
<TabItem value="linux" label="Linux">

JBR is bundled with the DEB/RPM package. If you run from source, install JBR into
`~/.jdks/` from [JBR Releases](https://github.com/JetBrains/JetBrainsRuntime/releases).

</TabItem>
<TabItem value="macos" label="macOS">

JBR is bundled with the DMG installer. If you run from source, install JBR from
[JBR Releases](https://github.com/JetBrains/JetBrainsRuntime/releases) or via
IntelliJ IDEA's Gradle JDK settings.

</TabItem>
</OsTabs>

## Install OmniSign Desktop

<OsTabs>
<TabItem value="windows" label="Windows">

Download `OmniSign-x.y.z.msi` (or `OmniSign-x.y.z.exe`) from
[GitHub Releases](https://github.com/pizavo/omnisign/releases) and run the installer. The installer
is **per-user**, so no administrator rights are required; it lets you choose the install directory
and creates a desktop shortcut plus an **OmniSign** Start-menu group. A portable ZIP
(`omnisign-desktop-x.y.z-win-portable.zip`) is also published.

The desktop and CLI are separate products, each with its own upgrade code and its own folder under
whichever install root you pick — `OmniSign` here, `omnisign-cli` for the CLI — so the two can be
installed side by side in either order.

</TabItem>
<TabItem value="linux" label="Linux">

**DEB (Debian / Ubuntu)**

```bash
sudo apt install ./omnisign_x.y.z_amd64.deb
```

**RPM (Fedora / RHEL)**

```bash
sudo dnf install ./omnisign-x.y.z-1.x86_64.rpm
```

Both packages install to `/opt/omnisign`. Installing through `apt` or `dnf`, rather than `dpkg -i`
or `rpm -i`, also installs the libraries the package needs, `xdg-utils` among them. The desktop
package (`omnisign`) and the CLI package (`omnisign-cli`, at `/opt/omnisign-cli`) are
independent and can be installed side by side. A portable archive
(`omnisign-desktop-x.y.z-linux-portable.tar.gz`) is also published.

</TabItem>
<TabItem value="macos" label="macOS">

Download `OmniSign-x.y.z.dmg` from
[GitHub Releases](https://github.com/pizavo/omnisign/releases) and drag OmniSign
to your Applications folder.

OmniSign installs as `/Applications/OmniSign.app`. The build is not code-signed or notarized, so
macOS blocks the first launch: allow it under **System Settings → Privacy & Security → Open
Anyway**, or clear the quarantine flag with `xattr -cr /Applications/OmniSign.app`. Since macOS 15,
right-clicking the app and choosing **Open** no longer offers that bypass.

The CLI keeps its own bundle in `/Applications/omnisign-cli/` rather than beside this one, so the two
can be installed side by side.

</TabItem>
</OsTabs>

:::note[For developers]
Run the desktop app from source (requires the JBR 25 toolchain):

```bash
./gradlew :composeApp:run
```

:::

## PDF file association

Every installer registers OmniSign as a handler for `application/pdf`, which places it in the
system's **Open with** menu. It does not claim the file type outright — the default PDF application
stays your choice:

<OsTabs>
<TabItem value="windows" label="Windows">

Right-click a PDF and choose **Open with → Choose another app**, select OmniSign and tick **Always
use this app**. The same assignment is available under **Settings → Apps → Default apps**.

</TabItem>
<TabItem value="linux" label="Linux">

The package installs a desktop entry declaring `MimeType=application/pdf`. Most desktop
environments offer **Properties → Open With** on a PDF; from a terminal:

```bash
xdg-mime default omnisign-OmniSign.desktop application/pdf
```

</TabItem>
<TabItem value="macos" label="macOS">

Select a PDF in Finder, press `Cmd+I`, pick OmniSign under **Open with** and click **Change All…**.

</TabItem>
</OsTabs>

The portable ZIP and tarball register nothing, since they are unpacked rather than installed.

## Configuration & log directories

OmniSign stores its configuration file and logs in platform-native directories.

<OsTabs>
<TabItem value="windows" label="Windows">

| Purpose       | Path                                         |
|---------------|----------------------------------------------|
| Configuration | `%APPDATA%\omnisign\config.json`             |
| Logs          | `%LOCALAPPDATA%\omnisign\logs`               |

</TabItem>
<TabItem value="linux" label="Linux">

| Purpose       | Path                                                                  |
|---------------|-----------------------------------------------------------------------|
| Configuration | `~/.config/omnisign/config.json`                                      |
| Logs          | `$XDG_STATE_HOME/omnisign` (fallback `~/.local/state/omnisign`)       |

</TabItem>
<TabItem value="macos" label="macOS">

| Purpose       | Path                                                  |
|---------------|-------------------------------------------------------|
| Configuration | `~/Library/Application Support/omnisign/config.json`  |
| Logs          | `~/Library/Logs/omnisign`                             |

</TabItem>
</OsTabs>

The desktop app, the CLI and scheduled renewals share the configuration file. If it exists but
cannot be read — a hand edit left it invalid, say, or a newer OmniSign version wrote a value this
one does not know — Settings reports that the configuration cannot be loaded, the Profiles panel
lists no profiles, signing, validation and timestamping run with the default settings, and
OmniSign never saves a change over the file, so nothing in it is lost. Fix the file, or move it
elsewhere to start over from the defaults. A save replaces the file in one step, so a save cut
short by a crash or a full disk leaves the previous configuration in place.

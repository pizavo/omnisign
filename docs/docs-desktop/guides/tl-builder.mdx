# Building a Custom Trusted List

OmniSign includes a built-in ETSI TS 119 612 Trusted List compiler that lets you create
your own Trusted List XML documents. This is useful when your organization's CA is not part
of the EU LOTL and you want OmniSign to trust it during validation and signing.

## Opening the builder

The Trusted List builder can be opened from two places:

- **Settings → Validation → Trusted Lists** — click the **Build Custom TL** button.
- **Profile editor → Trusted Lists** — click the **Build Custom TL** button within a profile's
  trusted list section.

![Trusted List builder dialog](/img/desktop/tl-builder-dialog.avif)

## 1. Fill in the scheme information

| Field                     | Description                                                                  |
|---------------------------|------------------------------------------------------------------------------|
| **Name**                  | Unique identifier for the list (also the suggested file name when you save). |
| **Territory**             | ISO 3166-1 alpha-2 code (e.g. `CZ`, `SK`, `XX` for custom).                  |
| **Scheme Operator Name**  | Name of the entity publishing this trusted list.                             |
| **Scheme name**           | What this list of trust anchors is called, e.g. *Internal PKI trust anchors*.|
| **Scheme information URI**| Where readers can find out about the scheme.                                 |

Below those fields, the **Scheme operator address** section collects the postal and electronic
address the standard requires of the publishing organization (clause 5.3.5):

| Field                  | Description                                                        |
|------------------------|--------------------------------------------------------------------|
| **Street address**     | Required.                                                          |
| **Postal code**        | Optional.                                                          |
| **Town or city**       | Required.                                                          |
| **State or province**  | Optional — for territories that use one.                           |
| **Country**            | Required. A country name or an ISO 3166-1 code.                    |
| **Contact URI**        | Required. Typically a `mailto:` address or an `https:` contact page.|

:::note[Why so many fields]
None of this is derivable from the certificates you are listing — it identifies organizations, not
keys — so it has to be typed in. The compiled document is validated against the ETSI schema before
it is written, and a list missing any mandatory field is rejected outright rather than produced in
a degraded form.
:::

## 2. Add Trust Service Providers (TSPs)

Click **Add TSP** to create a new provider entry. Each TSP card is expandable and contains:

| Field          | Description                                                           |
|----------------|-----------------------------------------------------------------------|
| **Name**       | Official name of the TSP.                                             |
| **Trade name** | Optional brand or trade name.                                         |
| **Info URL**   | URL pointing to the TSP's information page. Required (clause 5.4.5).  |

Each card also carries its own **Provider address** section, with the same six fields and the same
requirements as the scheme operator address above — the standard asks for one per provider as well
(clause 5.4.4).

### Add services to a TSP

Within each TSP card, click **Add Service** to register a trust service. Each service has:

| Field                  | Description                                                                  |
|------------------------|------------------------------------------------------------------------------|
| **Name**               | Human-readable name of the service.                                          |
| **Type identifier**    | ETSI service type URI. A dropdown provides common hints (e.g., CA/QC, TSA).  |
| **Status**             | ETSI service status URI. A dropdown provides common hints (e.g., granted).   |
| **Certificate**        | Path to the PEM or DER certificate file. Use the file picker to browse.      |

:::tip
The type identifier and status dropdowns include the most common ETSI URIs. You can also
type a custom URI directly into the text field.
:::

## 3. Register after compile

The **Register as a custom trusted list source after compiling** checkbox (checked by default)
controls whether the compiled Trusted List is staged into **Settings → Validation → Trusted Lists**.
Registration always targets the **global** scope, even when the builder was opened from a profile
editor, and is committed when you save the Settings dialog. When unchecked, the XML is written to
disk but not registered.

## 4. Compile

Click **Compile & Save** and choose where to write the Trusted List XML in the **Save As**
dialog (pre-filled with the list name). The compiler validates all required fields and writes
the file. On success, the dialog shows the output path and — when registration is enabled — the
resulting trusted list entry that was added.

Two fields are filled in for you and are not shown in the dialog: the status determination approach
is set to `http://uri.etsi.org/TrstSvc/TrustedList/StatusDetn/appropriate`, the generic approach
appropriate to a list published outside an EU member-state supervisory scheme, and the historical
information period is set to `65535` days, the value EU trusted lists carry.

### Errors

If validation fails (e.g., a required field is empty or a certificate file cannot be read),
the error message is displayed inline in the form — naming the missing field, and the provider it
belongs to when it is one of theirs. Compilation errors show a detailed message with optional
technical details.

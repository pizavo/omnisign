# Licensing

OmniSign is released under the **GNU Affero General Public License, version 3 or later**
(`AGPL-3.0-or-later`). Everything it distributes alongside itself carries its own licence, and this
page explains how those are tracked, where the notices end up, and what to do when a dependency
changes.

## Surfaces

The four packages ship genuinely different dependency sets, so every component is tagged with the
surfaces that actually contain it:

| Surface | Resolved from | Components |
|---|---|---|
| `cli` | `:cli` runtime classpath | 37 |
| `server` | `:server` runtime classpath | 46 |
| `desktop` | `:composeApp` JVM runtime classpath | 40 |
| `web` | `:composeApp` Wasm runtime classpath + the npm lockfile | 13 |

The gap between `desktop` and `web` is the point: the WebAssembly bundle contains none of the JVM
signing stack — no DSS, no PDFBox, no Bouncy Castle — because it delegates those operations to the
server. It instead ships npm packages no JVM build ever sees, MuPDF among them. A single merged list
would credit the wrong libraries on both sides, so the Credits dialog filters by the surface the
running build belongs to.

:::note[Why the web classpath is collected in composeApp]
Kotlin publishes its Wasm variants under its own usage value and target attribute, and a root-project
configuration set up to select them can no longer resolve the dependency BOMs the graph relies on.
Rather than fight that, `:composeApp:collectWebRuntimeCoordinates` resolves its own
`wasmJsRuntimeClasspath` and writes the coordinates to a file the generator reads as a plain input.
:::

## Where the notices live

| File | Contents |
|---|---|
| [`LICENSE.md`](https://github.com/pizavo/omnisign/blob/main/LICENSE.md) | OmniSign's own AGPL terms. |
| [`NOTICE.md`](https://github.com/pizavo/omnisign/blob/main/NOTICE.md) | Material copied *into* the repository — the Tabler icon set — plus the prominent notice EU DSS requires. |
| [`THIRD-PARTY.md`](https://github.com/pizavo/omnisign/blob/main/THIRD-PARTY.md) | Every bundled component, grouped by licence, with copyright, homepage and the verbatim `NOTICE` text each artifact ships. Generated. |
| `licenses/` | Full text of each licence named above. |

All four are installed with the application: next to the binary in the desktop and CLI packages,
inside the CLI and server fat JARs under `META-INF/legal/`, and beside `index.html` in the web
bundle. The desktop and web apps also surface them under **Help → Credits**.

Readers get a per-package view too, generated from the same data and filtered to that surface:
[CLI](/cli/credits), [server](/server/credits), [desktop](/desktop/credits) and
[web](/web/credits). Those pages are generated — edit the data, not the Markdown.

:::note[Adding a page under `docs-server/`]
The CLI, desktop and web sidebars are autogenerated, so a new page appears in the menu on its own.
`sidebars-server.ts` is enumerated by hand — the generated HTTP API category has to be spliced in —
so a page added there builds and is reachable by URL but stays out of the menu until it is listed.
:::

## Why this is not scraped from POMs

Published Maven metadata is not a reliable source of licence facts, and this project is a good
illustration:

- **DSS artifacts carry no licence text at all.** All 40 of them declare the licence only in their
  POM, which is not distributed with the application. The version and the "or later" grant come from
  the licence header in the DSS sources, not from the metadata.
- **Nine artifacts declare nothing**, inheriting from a parent POM that is not always resolvable.
- **The same licence is spelled many different ways** — Apache-2.0 alone appears under five distinct
  names.
- **Several components are dual-licensed**, and only a human can decide which branch a project takes.

npm packages are the one place where published metadata is dependable: the Wasm lockfile records a
`license` field per package. It is still not trusted as the source of truth, but the generator quotes
it in the failure message so a newly added package is quick to classify.

The curated facts therefore live in
[`gradle/third-party-licenses.json`](https://github.com/pizavo/omnisign/blob/main/gradle/third-party-licenses.json),
and the Gradle task only renders them.

## Licence elections

Where a component offers a choice, OmniSign records which branch it takes and why:

| Component | Offered | Taken | Reason |
|---|---|---|---|
| Logback | EPL-1.0 or LGPL-2.1 | **LGPL-2.1** | EPL-1.0 is incompatible with the GNU GPL family, so it could not be combined with an AGPL work. |
| veraPDF | GPL-3.0 or MPL-2.0 | **MPL-2.0** | MPL-2.0 §3.3 expressly allows distributing a Larger Work under a Secondary Licence such as the AGPL. |
| JNA | LGPL-2.1-or-later or Apache-2.0 | **Apache-2.0** | Carries no relinking obligation. |
| Jetty ALPN API | Apache-2.0 or EPL-1.0 | **Apache-2.0** | Compatible with the AGPL. |

MuPDF, which renders PDF pages in the web build, offers no choice: it is `AGPL-3.0-or-later`, the
same licence as OmniSign. Nothing extra follows from that beyond the attribution and the source
availability the AGPL already requires of the project.

:::note[Compatibility with the AGPL]
The weak-copyleft dependencies are combinable with an AGPL-3.0 work. LGPL-2.1 §3 permits taking a
copy under GPL-2.0-or-later, which upgrades to GPLv3, and AGPLv3 §13 expressly permits linking a
GPLv3 work with an AGPLv3 one; DSS additionally grants "or any later version", so it may equally be
taken under LGPL-3.0, itself a set of additional permissions on top of GPLv3.

Compatibility is not the whole obligation, though. LGPL-2.1 §6 separately requires *prominent notice*
that the library is used, *a copy of its licence*, and — because the app displays copyright notices
at runtime — the library's copyright among them with a pointer to that licence copy. That is what
`NOTICE.md`, `licenses/` and the Credits dialog exist for.
:::

## Regenerating after a dependency change

```bash
./gradlew generateThirdPartyNotices
```

This resolves all four surfaces, matches every artifact against the curated data, and rewrites
`THIRD-PARTY.md` plus the credits list the desktop and web apps read at runtime. Commit both.

**The task fails on any artifact it cannot account for**, so a new or bumped dependency cannot
silently ship an undocumented licence:

```text
No licence entry for 2 distributed artifact(s). Add them to gradle/third-party-licenses.json:
  - com.example:widget:1.4.0
  - widget-js@1.4.0 (lockfile declares MIT)
```

Add an entry keyed by one of:

- `groups` — a whole Maven group,
- `artifacts` — an exact `group:name`, which wins over a group match,
- `npmPackages` — an npm package name from the Wasm lockfile.

Name a licence from the `licenses` map at the top of the file. If the licence is one not yet used,
add it there too and drop its full text into `licenses/`.

CI verifies the committed output instead of rewriting it:

```bash
./gradlew generateThirdPartyNotices -PnoticesCheck=true
```

## Packaging notes

- **CLI fat JAR.** Merging ~180 jars collapses their `META-INF/LICENSE` and `META-INF/NOTICE` entries
  onto one path, so all but the first were being dropped. Those paths are now excluded outright and
  replaced by `META-INF/legal/`, which carries the aggregate — including every upstream `NOTICE`
  reproduced verbatim.
- **Installer licence.** The text the user accepts during installation is generated by
  `:generateInstallerLicense`: OmniSign's AGPL terms prefixed with a summary naming the third-party
  components, DSS explicitly, and pointing at the installed notices.

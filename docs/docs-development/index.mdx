# Development

This section is for people who want to **build OmniSign from source, change it, contribute to it, or understand how it
fits together**. If you only want to use the applications, start at
[Desktop](/desktop/), [Web](/web/), [Server](/server/), or [CLI](/cli/) instead.

OmniSign is a Kotlin Multiplatform project. One Gradle build produces four artifacts — a desktop
application, a browser client, an HTTP server, and a command-line tool — from a single shared core
built on the [EU DSS](https://github.com/esig/dss) library.

## Prerequisites

| Requirement | Needed for | Notes |
| --- | --- | --- |
| **JDK 25 or newer** | Everything | The Gradle wrapper runs on it; `--enable-native-access=ALL-UNNAMED` is already wired into `gradle.properties` |
| **JetBrains Runtime 25** | The desktop target only | `composeApp` pins its JVM toolchain to the JetBrains vendor |
| **Git** | Everything | |

You do **not** need a separate Node.js install to build the web target — the Kotlin/Wasm toolchain
provisions its own. Node is only required to work on this documentation site.

:::info[Why the desktop target insists on JBR]
`composeApp` sets `vendor.set(JvmVendorSpec.JETBRAINS)` on its JVM toolchain, because the desktop
window uses JetBrains Runtime's Custom Title Bar API. Anything that compiles or runs that target —
including `:composeApp:jvmTest` — therefore resolves a JBR 25 toolchain, not just `:composeApp:run`.

The [foojay toolchain resolver](https://github.com/gradle/foojay-toolchains) applied in
`settings.gradle.kts` will try to download one automatically. If it cannot, install JBR from the
[JetBrains Runtime releases](https://github.com/JetBrains/JetBrainsRuntime/releases) into `~/.jdks/`
and Gradle will detect it there. The `run` and packaging tasks fail with an explicit message when no
JBR is found, rather than silently falling back to another JDK.
:::

## First build

```bash
git clone https://github.com/pizavo/omnisign.git
cd omnisign
./gradlew build
```

On Windows use `gradlew.bat` in place of `./gradlew` throughout this section.

That compiles all four modules and runs their tests. To skip straight to running something, see
[Building and running](building.mdx).

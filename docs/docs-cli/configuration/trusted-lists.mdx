# Trusted Lists

Register custom ETSI Trusted List sources for signature validation. These are used
alongside (or instead of) the EU LOTL when validating signatures from CAs that are
not part of the eIDAS trust framework.

## `config tl add`

Register a custom trusted list source.

| Option                    | Description                                                                 |
|---------------------------|-----------------------------------------------------------------------------|
| `-n, --name <name>`       | **(Required)** Unique label for this trusted list                           |
| `-s, --source <url/path>` | **(Required)** HTTPS URL or file path to the TL XML                         |
| `--signing-cert <path>`   | PEM/DER certificate to verify the TL's XML signature (strongly recommended) |
| `-p, --profile <name>`    | Store in the given profile instead of the global config                     |

## `config tl list`

List all registered custom trusted lists.

```bash
omnisign config tl list
omnisign config tl list --profile university
```

## `config tl remove <name>`

Remove a registered custom trusted list.

```bash
omnisign config tl remove my-org-tl
```

## `config tl refresh`

Force an immediate online refresh of the EU LOTL and every custom trusted list into the shared
on-disk cache. Useful as a maintenance step so subsequent validations start from a freshly
refreshed cache instead of paying the download on a validation's critical path.

```bash
omnisign config tl refresh
```

## `config tl build` — Build custom trusted lists

The TL builder lets you create your own ETSI TS 119612-compliant Trusted List XML,
useful for organisations that need to trust internal CAs.

| Subcommand                                                         | Description                                                |
|--------------------------------------------------------------------|------------------------------------------------------------|
| `config tl build create <name>`                                    | Guided interactive wizard to build a complete trusted list |
| `config tl build list`                                             | List all stored TL builder drafts                          |
| `config tl build show <name>`                                      | Show the contents of an existing draft                     |
| `config tl build tsp add <draft> --name <tsp-name>`                | Add a Trust Service Provider to a draft                    |
| `config tl build tsp remove <draft> <tsp-name>`                    | Remove a TSP from a draft                                  |
| `config tl build service add <draft> <tsp-name> --name <svc> ...`  | Add a trust service to a TSP in a draft                    |
| `config tl build service remove <draft> <tsp-name> <service-name>` | Remove a service from a TSP                                |
| `config tl build compile <draft>`                                  | Compile a draft to a TL XML and optionally register it     |
| `config tl build delete <draft>`                                   | Delete a draft                                             |

Both `create` and `compile` accept `-p, --profile <name>` to register the compiled list into a
profile's validation config instead of the global config.

### What the standard requires

The compiled document is validated against the ETSI TS 119612 schema before it is written, so a
draft missing a mandatory field cannot be compiled. None of these fields can be derived from the
certificates you are listing — they identify organisations, not keys — so they have to be supplied
while the draft is authored:

- **Scheme level** — operator name and address (clause 5.3.5), scheme name (5.3.6) and a scheme
  information URI (5.3.7).
- **Per provider** — a postal and electronic address (clause 5.4.4), an information URI (5.4.5),
  and at least one service.

Two further fields are filled in for you and rarely need changing: the status determination
approach defaults to `http://uri.etsi.org/TrstSvc/TrustedList/StatusDetn/appropriate`, the generic
approach appropriate to a list published outside an EU member-state supervisory scheme; and the
historical information period defaults to `65535` days, the value EU trusted lists carry.

`config tl build show <draft>` marks anything still outstanding, and `compile` names every gap at
once rather than stopping at the first:

```text
❌ Trusted list 'my-org' cannot be compiled — ETSI TS 119612 requires: provider
'Example University CA' information URI, provider 'Example University CA' address
```

:::note[Drafts are created interactively]
`config tl build create` is the only command that creates a draft, and it is the only place the
scheme-level fields can be entered — the remaining subcommands edit the providers and services of
a draft that already exists. Run `create` first, then use `tsp add` and `service add` to fill in
or amend the rest non-interactively.
:::

### `tsp add` options

| Option                       | Description                                                                     |
|------------------------------|---------------------------------------------------------------------------------|
| `--name, -n <name>`          | **(Required)** Official name of the Trust Service Provider                      |
| `--info-url <url>`           | URL pointing to the TSP's information page or registration. Required to compile |
| `--street <street>`          | Street address. Required to compile                                             |
| `--locality <town>`          | Town or city. Required to compile                                               |
| `--country <country>`        | Country name or ISO 3166-1 code. Required to compile                            |
| `--electronic-address <uri>` | Contact URI, e.g. `mailto:info@tsp.example`. Required to compile                 |
| `--trade-name <name>`        | Optional trade/brand name                                                       |
| `--state <state>`            | Optional state or province                                                      |
| `--postal-code <code>`       | Optional postal code                                                            |

Only `--name` is enforced by the command itself; the rest are checked at compile time, so a
partially filled provider can be saved and completed later by running `tsp add` again with the
same `--name`.

### `service add` options

| Option              | Description                                                                                          |
|---------------------|------------------------------------------------------------------------------------------------------|
| `--name, -n <name>` | **(Required)** Human-readable name of the service                                                    |
| `--type-id <uri>`   | **(Required)** Service type identifier URI (e.g. `http://uri.etsi.org/TrstSvc/Svctype/CA/QC`)        |
| `--status <uri>`    | **(Required)** Service status URI (e.g. `http://uri.etsi.org/TrstSvc/TrustedList/Svcstatus/granted`) |
| `--cert <path>`     | **(Required)** Path to the PEM or DER certificate representing the service                           |

### `compile` options

| Option                 | Description                                                                      |
|------------------------|----------------------------------------------------------------------------------|
| `-o, --out <path>`     | Output path for the XML file (default: `<draft-name>.xml` in current directory)  |
| `--register`           | After compiling, automatically register the output file as a custom TL source    |
| `-p, --profile <name>` | When `--register` is used, store the TL in this profile instead of global config |

### Example workflow

```bash
# Create the draft. The wizard collects the scheme name, information URI and the
# scheme operator's address, then offers to add providers and services inline.
omnisign config tl build create my-org

# Providers can also be added afterwards, without the wizard. Give the address
# and information URI here, or the draft will not compile.
omnisign config tl build tsp add my-org \
  --name "Example University CA" \
  --info-url "https://pki.example.edu" \
  --street "Univerzitni 8" \
  --locality "Plzen" \
  --postal-code "301 00" \
  --country "CZ" \
  --electronic-address "mailto:pki@example.edu"

# Add a service to the TSP
omnisign config tl build service add my-org "Example University CA" \
  --name "CA/QC Service" \
  --type-id "http://uri.etsi.org/TrstSvc/Svctype/CA/QC" \
  --status "http://uri.etsi.org/TrstSvc/TrustedList/Svcstatus/granted" \
  --cert /path/to/ca-cert.pem

# Review the draft and confirm nothing mandatory is outstanding
omnisign config tl build show my-org

# Compile the draft and register it
omnisign config tl build compile my-org --register

# List all drafts
omnisign config tl build list

# Verify it's registered
omnisign config tl list
```

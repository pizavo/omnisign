# schedule

Controls the OS-level daily job that invokes `omnisign renew` automatically, and manages
the renewal job entries stored in the configuration.

## `schedule install`

Register (or replace) the daily `omnisign renew` job with the OS scheduler
(systemd on Linux, launchd on macOS, Task Scheduler on Windows).

```
omnisign schedule install [options]
```

| Option              | Description                                                                                              |
|---------------------|----------------------------------------------------------------------------------------------------------|
| `--cli-path <path>` | Absolute path to the omnisign binary. Auto-detected when omitted (may fail for `java -jar` invocations). |
| `--hour <0-23>`     | Hour of day at which the job runs. Default: `2`                                                          |
| `--minute <0-59>`   | Minute at which the job runs. Default: `0`                                                               |
| `--log-file <path>` | Absolute path to an append-only log file for renewal output.                                             |

## `schedule uninstall`

Remove the daily `omnisign renew` OS job if it exists.

```bash
omnisign schedule uninstall
```

## `schedule status`

Show whether the daily `omnisign renew` OS job is registered, and summarise the most recent run.

```bash
omnisign schedule status
```

```
✅ Daily renewal job is installed.

Last successful run: 12/08/2026 02:00
Last run: 13/08/2026 02:00 — completed with errors (checked 42, renewed 3, skipped 38, errors 1)
⚠ 1 unsuccessful run(s) since the last success.
   - /archive/contract.pdf: renewal failed: the timestamp server could not be reached
```

Renewal runs in a separate process started by the OS scheduler, so this is where you find out what it
did. Three lines are worth knowing:

- **Last successful run** — the clock the staleness warning measures against. `never` means no run has
  ever completed cleanly.
- **Last run** — its outcome and counts. `interrupted` means the run began and was killed before it
  could finish, which is what a restart landing on the scheduled time does.
- **A renewal run has been in progress since …** — shown while a run is executing. If it appears when
  nothing is running, the run that set it was killed and the next run will record it as interrupted.

:::note[Why an interrupted run only shows up here and in the desktop app]
A killed process writes no run record, fires no notification and logs nothing, so the run that
follows it is the first thing able to report it. Until then the status is the only place the
interruption is visible. Three interruptions in a row do raise a notification — see
[`renew`](renew#os-notifications).
:::

## `schedule job` — Manage renewal jobs {/* #schedule-job */}

Renewal jobs define which PDF files are monitored for archival timestamp expiry and
with which settings (TSA profile, buffer window, notification behavior).

| Subcommand                   | Description                      |
|------------------------------|----------------------------------|
| `schedule job add <name>`    | Add or replace a renewal job     |
| `schedule job list`          | List all configured renewal jobs |
| `schedule job remove <name>` | Remove a renewal job             |

### `schedule job add` options

| Option                  | Description                                                                                                                                                                                                                    |
|-------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `-g, --glob <pattern>`  | **(Required, repeatable)** Glob pattern matching PDF files to watch. Must be an absolute path, and must be a pattern the platform can parse — an unclosed `[` or `{` is rejected here rather than at 2 a.m.                    |
| `-b, --buffer-days <n>` | Days before timestamp certificate expiry at which re-timestamping is triggered. Applies to B-LTA documents, the only case with something to wait for. Default: `90`                                                            |
| `-B, --backups <n>`     | Timestamped pre-renewal `.bak` copies to keep per file (`0` disables backups). Default: `3`                                                                                                                                    |
| `--profile <name>`      | Named configuration profile to use for TSA and revocation settings                                                                                                                                                             |
| `--log-file <path>`     | Absolute path to an append-only log file for this job's renewal output                                                                                                                                                         |
| `--no-notify`           | Disable OS desktop notifications for this job                                                                                                                                                                                  |
| `--no-promote`          | Only maintain documents already at B-LT or above; do not bring up B-B / B-T ones. See [the deadlines](renew#what-needs-renewal-means) before using it — the chance to add validation data expires with the signing certificate |

### Examples

```bash
# Add a renewal job that watches all PDFs under a directory
omnisign schedule job add thesis-archive \
  --glob "/home/user/docs/**/*.pdf" \
  --buffer-days 60 \
  --profile university

# Install the daily OS scheduler job
omnisign schedule install --hour 3 --log-file /var/log/omnisign-renew.log

# Check scheduler status
omnisign schedule status
```
